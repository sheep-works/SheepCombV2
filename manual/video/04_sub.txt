SheepComb Webの使い方4 QAとAIチェック

この動画では、翻訳の品質保証について説明します。
翻訳における品質保証は、Quality Assurance、略して「QA」と呼ばれています。

多くの翻訳支援ツールで取り入れられている手法としては、主にスペルチェックのほか、
・原文と訳文で数字に違いがないか
・タグや変数は崩れていないか
・用語集の指定に反していないか
などが機械的にチェックされます。

SheepComb では、これらの機械的なチェックに加え、AIを利用したセマンティックな校正リクエストにも対応しており、翻訳・チェック作業の最後のステップとして、第三者の視点を加えられるように設計されています。

使い方も非常にシンプルです。
まずは対訳表のパースから構造化まで進めておきます。

「管理」のページに進むと、QAの項目があります。
バージョン 1.0.0 現在で実行できるQA項目は、

数字不一致
タグ / プレースホルダー
用語集含有
整合性
修正漏れ
の5種類です。
チェックしたい項目が選択されていることを確認したら、「実行」をクリックします。
しばらく待つと結果が表示され、タイプごとにフィルタリングすることも可能です。

なお、「整合性チェック」は、原文同士が非常に似ているのに、訳文同士の類似度が低い場合にアラートを出す機能です。
また、「修正漏れ」は、翻訳支援ツール「SheepWeave」で翻訳しているケースを想定したもののため、他のツールをお使いの場合はチェックを外しておいても構いません。

このように、QA機能は数字の入力ミスやタグの欠落などをすばやく検出してくれます。

一方で、これはあくまで「機械的なチェック」です。
文脈に応じた意訳やローカライズの適切さまでは判断しませんし、誤訳かどうかを判定するものでもありません。
たとえば、英語の「January」を日本語で「1月」と自然に訳した場合でも、機械的には「数字のエラー」として検出されます。
そのため、機械的なQAはあくまで「うっかりミスを洗い出すための補助」と捉え、最終的には人間が確認する必要があります。

これに対し、文脈に合ったローカライズができているか、誤訳がないかを柔軟に判定するのが、AIによる「セマンティックなチェック」です。

AIによるチェックを行うには、SheepComb Web 単独ではなく、
中継アプリである「SheepBobbin」と、
Ollama や LM Studio などの「ローカルLLMアプリ」、
または ChatGPT、Claude、Google AI Studio、DeepSeek といった「クラウドLLMのAPI」が必要となります。

「API」のページに移動したら、まずは「チャンク作成」をクリックしてください。
「チャンク」とは、AIが文脈を保ちながら無理なく処理できるよう、対訳データを適切な長さに小分けにしたものです。
デフォルトでは4,000文字前後で分割されます。
急ぎの場合はチャンクサイズを大きくしたり、翻訳精度や安定性を重視する場合は小さくしたり、といった調整が可能です。

チャンクが作成できたら、SheepBobbin を起動し、接続用のパスワードを双方に入力して連携します。
その後、SheepBobbin 側で利用したい LLM の情報を設定し、SheepComb Web の画面に戻ります。

プロンプトの内容を確認したら、あとは「全チャンク処理」をクリックするか、個別に処理したいチャンクの更新アイコンをクリックします。
SheepBobbin を経由して AI がプロンプトどおりに校正・チェックを行い、画面上に結果が出力されます。

なお、SheepComb では
・チャンクの作成モードとして「Raw / ShWvData / Similarity / Diff / Direct」の5種類
・処理タイプとしても「Check / Translate / Proof / Diff / Custom」の5種類
を用意しています。
